rustmanifest :: методология как код

RAprogramm/RustManifest · rust 1.95.0 · edition 2024

Аннотация

rustmanifest — детерминированный движок понимания Rust-кода: методология исполняется как правила, ни одной модели в контуре; каждая находка несёт трассу вывода, одинаковый вход даёт байт-в-байт одинаковый выход. Ярусы: regex (3 правила), AST (8), семантика воркспейса (10).

На корпусе из четырёх репозиториев (190 769 строк) у 6 правил из 21, прошедших разбор точности, — 0 ложных; у четырёх из шести ворота дают 0 находок, recall не измерен. Машина Цетлина прошла порог допуска (+17.3 п.п. macro-F1 к логрегрессии); метки — из той же базы фактов: замер выразимости, не открытия. Авто-правки — шесть сквозных тестов; слои архитектуры из графа вызовов — частично.

§01

Постановка проблемы

§

Задача — исполнять стайлгайд проекта как код, без модели в контуре понимания. Имя функции — обещание (get_/is_ — наблюдение), doc-комментарий — обещание длиннее; противоречие с наблюдаемым поведением тела решается правкой обещания (RM-QUAL-001, RM-QUAL-002). Тот же движок — ворота и для человека, и для агента через MCP.

§02

Контекст и пробелы (июль 2026)

§

Занято: clippy — 700+ линтов, но per-crate; dylint — нестабильный rustc_* API; ast-grep и semgrep — чистый синтаксис; Miri, Kani, Creusot — верификация, не извлечение фактов. CodeQL (Rust GA, октябрь 2025) — референс схемы фактов, но проприетарен, не cargo-native; ra_ap_* нестабилен, rustc_public — nightly-only. LLM-ревьюеры недетерминированы; «статика находит — LLM объясняет» — стандарт отрасли (ZeroFalse: F1 0.912/0.955 — docs/PLAN.md §1.5). Пустые ниши:

  • архитектурные инварианты уровня воркспейса — ArchUnit для Rust отсутствует;
  • манифест правил, единая база фактов, трасса вывода — детерминированные ворота для LLM-патчей;
  • машина Цетлина на исходном коде — публикаций не нашлось.

Источники и методика поиска (живые источники, август 2026) — docs/RESEARCH-2026-07-behavioral-tier.md §1 и docs/PLAN.md §1; здесь — конспект.

§04

Метод

§

Конвейер по схеме CodeQL/Glean/Kythe: тупой тотальный экстрактор → типизированная база фактов → декларативный вывод. Правило — силлогизм: таксономия (данные, не мнение) даёт класс обещания, факты тела — наблюдение, противоречие — находка с трассой; каждое уточнение точности — снова данные. «Консервативные ворота» — условия доказуемости находки: не доказано — правило молчит. В обучаемом слое — фиксированный seed и булева оценка клауз; клаузы описывают код, находок не порождают. Clippy не дублируется: наличие секций rustdoc — missing_errors_doc, истинность — наша; redundant_clone на MIR — делегирование.

§06

Границы и открытые вопросы

§
  • Смещение корпуса: сторонний код — только fork-hyper, остальные три репозитория того же автора; валидации на стилистически независимом чужом коде нет — главный внешний риск для «0 ложных».
  • Разметка ложных — один автор, без второго аннотатора и формализованного протокола; критерий — формулировка правила.
  • Recall не измерен: только точность на корпусе; ворота могли купить 0 ложных ценой молчания.
  • Достижимость 58.6 % на masterror (Табл. 3) не объяснена — открытый вопрос.
  • Поток владения аппроксимируется формой использования, не borrow-check; dataflow — за MIR-уточнителем.
  • Макросы — зона недоказуемости: объявления в макрообёртках дают молчание, не находку.
  • Ребро вызова — только при единственном совпадении; ложное ребро хуже отсутствующего.
§07

Программа исследования

§
  • в работе переименования с отпечатками поведения — rename-операция в слое правок;
  • спроектировано семантический экстрактор (фаза 4): ra_ap_hir, pinned-версия, бюджет на churn;
  • заблокировано MIR-уточнитель (фаза 6): rustc_public, ждёт выхода на crates.io;
  • заблокировано discovery-прогон обучаемого яруса: реальные метки accept/suppress, до них выученные правила не поставляются;
  • спроектировано Datalog-вывод (фаза 3): Ascent, когда объём фактов оправдает; HTTP/OAuth, делегирование clippy.

«Заблокировано» — внешняя зависимость, не дефект.
