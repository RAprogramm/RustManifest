rustmanifest :: методология как код

RAprogramm/RustManifest · rust 1.95.0 · edition 2024

Аннотация

rustmanifest — детерминированный движок понимания Rust-кода: методология проекта исполняется как правила, ни одной модели в контуре анализа. Три яруса извлечения фактов — regex, AST, семантика воркспейса — питают пакет из 21 правила; каждая находка несёт полную трассу вывода, одинаковый вход даёт байт-в-байт одинаковый выход. На корпусе из четырёх репозиториев (190 769 строк) консервативные ворота дали 0 ложных срабатываний; recall не измерен — точность прежде охвата. Обучаемый слой на машине Цетлина прошёл ворота допуска: macro-F1 0.9955 против 0.8224 у логрегрессии на идентичных признаках. Межфайловые авто-правки безопасны под доказуемыми воротами; слои архитектуры выведены из графа вызовов.

§01

Постановка проблемы

§

Задача — исполнять стайлгайд проекта как код, без модели в контуре понимания: одинаковый вход — байт-в-байт одинаковый выход, каждая находка несёт полную трассу вывода. Код — единственная исполняемая истина: имя функции — обещание (get_/is_ — наблюдение), doc-комментарий — обещание длиннее; тело лгать не может, и противоречие решается правкой обещания (RM-QUAL-001, RM-QUAL-002). Методология исполняется, а не читается; тот же движок — ворота и для человека, и для агента через MCP.

§02

Контекст и пробелы (июль 2026)

§

Занято: clippy — 700+ линтов, но per-crate; dylint требует нестабильного rustc_* API; ast-grep и semgrep — чистый синтаксис; Miri, Kani, Creusot — верификация, не извлечение фактов. CodeQL (Rust GA, октябрь 2025) — референс схемы фактов, но проприетарен и не cargo-native; ra_ap_* нестабилен, rustc_public — nightly-only. LLM-ревьюеры недетерминированы; связка «статика находит — LLM объясняет» — уже стандарт отрасли (ZeroFalse: F1 0.91–0.95). Пустые ниши:

  • архитектурные инварианты уровня воркспейса — ArchUnit для Rust отсутствует;
  • манифест правил, единая база фактов, трасса вывода — детерминированные ворота для LLM-патчей;
  • машина Цетлина на исходном коде — публикаций не нашлось.

§04

Метод

§

Конвейер по схеме CodeQL/Glean/Kythe: тупой тотальный экстрактор → типизированная база фактов → декларативный вывод. Правило — силлогизм: таксономия (данные, не мнение) даёт класс обещания, факты тела — наблюдение, противоречие — находка с трассой; каждое уточнение точности — снова данные, не костыль. Детерминизм всюду, включая обучаемый слой: фиксированный seed, булева оценка клауз; клаузы описывают код и никогда не порождают находок. Clippy не дублируется: наличие секций rustdoc — missing_errors_doc, истинность — наша; redundant_clone на MIR — делегирование.

§06

Границы и открытые вопросы

§
  • Поток владения аппроксимируется формой использования, не borrow-check; dataflow — за MIR-уточнителем.
  • Макросы — зона недоказуемости: объявления в макрообёртках дают молчание, не находку.
  • Recall не измерен: размеченной полноты нет, только точность на корпусе.
  • Ребро вызова — только при единственном совпадении; ложное ребро хуже отсутствующего.

Принципы

Детерминизм
— байт-в-байт одинаковый выход; трасса вывода на каждой находке; фиксированный seed даже в обучаемом слое.
Код — единственный источник истины
— имя и документация могут лгать, тело — нет; противоречие решается правкой обещания.
Точность прежде охвата
— каждое правило разбирается на корпусе 190 тысяч строк; два настоящих срабатывания лучше тринадцати сырых.
Инструмент ловит себя
— цикл модулей в собственном движке найден первым прогоном overview и распутан тем же днём.
